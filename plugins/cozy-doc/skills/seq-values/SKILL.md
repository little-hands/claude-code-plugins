# seq-values

処理の流れを、**図で形を掴ませ、実値で中身を掴ませる**成果物にする。

## 0. 引数と出力先

| 引数 | 出す物 | 開く | 中身 |
|---|---|---|---|
| なし / `html`（既定） | スタンドアロン HTML 1 枚 | `open` でブラウザに出す | 全節（0 スコープ・1 図・2 実値） |
| `md` | 貼り込み用の Markdown | 開かない。パスだけ伝える | **図＋矢印ごとの実値だけ**（0 節は落とす） |

**出力先の既定は `/tmp`。** どちらの形式も `/tmp/seq-$(date +%Y%m%d-%H%M)-<slug>.{html,md}` に書く。
**ユーザーが置き場所を指示したら、そこに書く**（「この設計書に足して」「docs/ に置いて」等）。既存ファイルへ足す場合は、書く前に対象と挿入位置を提示して確認を取る。

### 詳細度 — `full` / `public`

出力形式（html/md）とは別の軸。組み合わせて指定できる（`public` 単体でも `html public` でもよい）。

**判定は機械的にする。「主題に関係あるか」のような読み手の解釈が要る基準は使わない。**

| 引数 | 意味 |
|---|---|
| なし / `full`（既定） | **参加者をまたぐかどうかに関わらず、呼び出し連鎖のすべてのメソッド呼び出しを、それぞれ独立した矢印・実値ブロックとして書く。** `.step` 内の省略のアコーディオンは使わない — `full` は「省略なし」の指定だから。スコープ外の断り（`.scope` 直下のアコーディオン）は詳細度と無関係に置く |
| `public` | **参加者（モジュール）をまたぐ呼び出しだけを矢印にする。** 同じ参加者の実装内で完結する呼び出し連鎖（ヘルパー関数・ループ・多段の私的な呼び出し）は、たとえ呼ばれる関数の名前が public（先頭アンダースコアなし）でも矢印にしない — **判定は「このシナリオで実際に参加者の境界をまたいだか」であって、関数の命名規則ではない**。参加者をまたぐ呼び出しは、そのシナリオで起きるものを**省略せず全部**矢印にする（ここは `full` と同じ）。同一参加者内に折りたたんだ箇所には「省略のアコーディオン」（後述）を添える |

**参加者の切り方は書き手が決める。** 1 つの参加者に複数の実装ファイル・ディレクトリを割り当ててよい（「mermaid の書き方」節にある `参加者名（クラス名／ファイル名／ディレクトリ名）` の書き方を参照）。**割り当てを決めたら、その粒度で機械的に境界判定する** — 「ここは重要そうだから参加者を分けよう」のような、境界を引き直して結果を作る判断はしない。境界は先に決め、あとから動かさない。

**`public` は「参加者をまたぐ呼び出しは全部見せる・またがない呼び出しは全部隠す」であって、`full` の中間ではない。** 主題外に見える参加者間呼び出しでも、実際に呼ばれるなら矢印にする（省略しない）。逆に参加者内で完結する呼び出しは、それがどれだけ興味深くても矢印にしない（自己矢印 1 本にまとめて中身は `.step` の説明・コードで語る）。

**`public`・`full` とも、スコープの外側（0 節の「含まない」に書いた範囲）は書かない。** 詳細度はスコープの内側をどこまで細かく見せるかの軸で、スコープを広げる軸ではない。

**`full` では §5 の「`.step` が 10 個を超えたら描き直す」を適用しない。** その上限が守るのは「1 枚で読み切れる」ことで、`full` は意図的にその原則を外す指定だから。`public` はこの上限の対象内だが、**「10 個以内に収まる」は目安であって保証ではない** — 参加者境界をまたぐ呼び出しが実際に多いシナリオでは 10 個を超えることがある。超えても、境界をまたぐ呼び出しを隠して数を減らしてはいけない（§「省略のアコーディオン」の「参加者境界をまたぐ呼び出しは `public` でも省略しない」に反する）。**超えたときは、対象コードの現物を数えてから、2 で決めたスコープを狭めて描き直す**（10 個以内に収まらないこと自体は、参加者間のやりとりが多いという事実で、機械的な基準を歪めてまで隠す理由にはならない）。

## この構成の芯

普通のシーケンス図は「レート API を呼ぶ」までしか語らない。
戻り値のどこを使うか・丸めをどちらに倒すかは記法では書けず、読み手ごとに解釈が割れる。
**図（流れ）と実値（中身）を別セクションに分け、番号で対応させる**のが、この構成の狙い。

守る原則は 3 つ。

1. **矢印に番号を振り、実値も同じ番号で並べる**
2. **1 本のシナリオで通す**（節ごとに例を変えない）
3. **うまくいかない例を必ず入れる**（`.step.is-fail` を最低 1 つ）

そして **図には数値を入れない**。図と実値の両方に数字を置くと、片方だけ直したときに食い違う。

## 使わない場面

- **図だけ欲しい時** — mermaid のコードブロックをそのまま返す。HTML にしない
- **`.drawio` が欲しい時** — `draw-io` スキルへ
- **実値が用意できない時** — コードも実データも無く実値を推測で埋めるくらいなら、このスキルは使わない。実値の裏取りが取れないことをそのまま伝える

## 手順

### 1. 対象を特定する

会話の文脈から、何の流れを図にするかを判断する。直近で読んだコード・議論した設計・調査結果が対象。
**文脈から一意に決まらないときだけ** `AskUserQuestion` で候補を出して確認する。

対象が実コードなら、**先に読んでから書く**。参加者・呼び出し順・エラー時の分岐・実際の値（レスポンス JSON、SQL の行、計算式）を拾う。実値をでっち上げない — コードや実データから取る。

### 2. スコープを 1 文で決める

「どこからどこまでか」を決め、`.scope` に書く。含まないものも明記する（例: 「会員登録・カート・決済は含まない」）。
ここが曖昧だと図が肥大する。**1 画面 1 リクエスト程度**に絞る。

### 3. テンプレートから組み立てる

`assets/template.html` を Read し、`{{...}}` を埋めた**全文を Write で出力先に書く**。

テンプレートは**骨組みが 1 つずつ入っているだけ**なので、次は必ず数に合わせて増減させる:

- `.step` … 実値ブロックの数だけ複製する（テンプレは正常系 1 つ＋失敗系 1 つのみ）
- 決めごとテーブルの `<tr>` … 決めごとの数だけ複製する
- `.tips` の `li` … 3 つ固定（原則そのものなので変えない）

**プレースホルダは 1 つも残さない。使わないセクションは丸ごと削る**（0 節の決めごとテーブルなど、対象によっては不要）。
`{{TITLE}}` は `<title>` と `<h1>` の 2 箇所にあるので両方置換する。

セクション構成:

| 節 | 中身 | 省略 |
|---|---|---|
| header | タイトル・リード文・原則 3 つ（`.tips`） | 不可 |
| 0 | ユーザーストーリー・スコープ・決めごとテーブル | ストーリーの扱いは「ユーザーストーリーの型」を参照 |
| 1 | mermaid シーケンス図（数値なし） | 不可 |
| 2 | 矢印ごとの実値（`.step` の並び） | 不可 |

**1 と 2 は `<div class="split">` で包む**（テンプレートに入っている）。広い画面では左に図・右に実値の 2 カラムになり、図が貼り付いたまま実値だけスクロールする。**この構成が効くのは「番号で対応させる」からで、視線が図と値を往復できるほど対応が追いやすい。** 狭い画面では自動で縦積みに戻る。

**まとめ・所感の節は作らない。** 最後の `.step` で終わる。言いたいことは実値そのものが語る。

使えるクラスは「マークアップ辞書」を参照。

#### 実値ブロックには出どころを書く

**各 `.step` に、その値がどこから来たのかを必ず添える。** `h3` の直後に `<p class="src">` を置く。

```html
<h3>レートを問い合わせる — 時刻も一緒に渡す</h3>
<p class="src">fx/rate_client.py · fetch_rate()</p>
```

**読み手が現物へ飛べるようにするため**で、同時に**裏取りの宣言**でもある。

**出どころは 3 種類。どれかを必ず書く。**

| 種類 | 書き方 |
|---|---|
| コードから取った | `fx/rate_client.py · fetch_rate()`（パスはリポジトリルート起点） |
| 文書・実データ・コマンド出力から取った | `議事録 2026-09-01 · 3 項` / `他社 API リファレンス · /v2/rates` / `顧客提供の pptx 3 ページ目` / `$ python3 fx/cli.py 29.99 USD` |
| **まだ存在しない**（これから作る設計） | `設計案 (未確認)` |

**コードが無い題材でも「書けない」は起きない。** 3 種類目があるので、**存在しないファイル名をでっち上げてはいけない**。全ブロックが `設計案 (未確認)` になる図もあってよい — 読み手が「全部これから決めること」と一目で分かるのが狙い。

- 1 つの矢印が複数の場所をまたぐときは **`→`** で繋ぐ（`fx/rate_client.py RateUnavailable → fx/cli.py main()`）
- `check.py` が `src_missing` で数え、**欠けている矢印番号を出す**（`src_missing=2 ['2', '4c']`）。1 件でもあれば NG。空の `<p class="src"></p>` も未記載として数える

`md` では見出しの次の行に、同じ内容を置く。**行の先頭は必ずインラインコードで始める**（`check.py` がそれを目印に見るため。`設計案 (未確認)` のような文言も `` `設計案 (未確認)` `` と囲む）。

````markdown
## 3. レートを問い合わせる — 時刻も一緒に渡す

`fx/rate_client.py` · `fetch_rate()`

```python
fetch_rate("USD", now=1_757_400_000.0)
```
````

#### 省略のアコーディオン（`public` で同一参加者内へ折りたたんだとき／スコープ外の断り）

`public` で、参加者境界をまたがない呼び出し連鎖を 1 本の自己矢印（または前後の参加者間矢印）に折りたたんだら、その `.step` に `<details class="omitted">` を 1 つ添える。0 節の「含まない」に書いたスコープ外の断りは、詳細度に関わらず `.scope` 直下に置く（下の表）。**独立した「省略した点」セクションを最後にまとめて作らない** — 一覧化すると読み手が図と往復できず「見づらい」（実際に指摘された失敗形）。省略は、それが起きた場所に埋め込む。

```html
<details class="omitted">
  <summary><strong>省略されているもの：</strong>一言で何を潰したか</summary>
  <p class="why">なぜ省略したか — 1〜2 文</p>
  <div class="prompt-box">
    <pre class="code" id="omit-4a">この図（絶対パス）の Step 4a を、どう展開するかを指示する再生成プロンプト</pre>
    <button class="copy-btn" type="button" data-target="omit-4a">📋 このプロンプトをコピー</button>
  </div>
</details>
```

- `id` は `omit-{badge番号}`（`.scope` 直下なら `omit-scope`。スコープ外の断りが複数あるときは `omit-scope-{語}` で分ける）。`data-target` と必ず一致させる — ずれるとコピーボタンが無反応になる。**`check.py` はここを見ない**ので、`id="omit-` と `data-target="omit-` を `grep` で突き合わせて自分で確認する
- `summary` は**一言**（20〜30 字程度）。詳しい理由は `.why` へ落とす — 一覧性を保つのはここ
- プロンプト文は「このファイル（絶対パス）の、どの Step を、どう展開するか」を書き、読み手が別セッションでそのまま貼れる形にする
- CSS（`details.omitted` / `.prompt-box` / `.copy-btn`）と JS（クリップボードコピー。`navigator.clipboard` が無い環境向けの `execCommand` フォールバック込み）は `assets/template.html` に入っている。**新しく書き足さない**
- **同一参加者内への折りたたみ vs スコープ外を混同しない。**

  | 種類 | 判定 | 置き場所 | `full` で展開するか |
  |---|---|---|---|
  | 参加者境界をまたがない呼び出し連鎖を折りたたんだ | 機械的（呼び出しが参加者をまたぐか） | 折りたたんだ `.step` の中 | する |
  | 0 節の「含まない」に書いたスコープ外 | スコープの宣言（工程 2 で決める） | `.scope` の直下（`.step` の中には置かない） | しない |

  **参加者境界をまたぐ呼び出しは、`public` でも省略しない。** 省略のアコーディオンを付けてよいのは「同一参加者内で完結する」場合だけ — 「この参加者間呼び出しは主題から外れるから省く」という判断はしない（それは境界をまたぐ呼び出しの隠蔽であって、機械的な基準から外れる）。

#### ユーザーストーリーの型

`blockquote.story` は、アジャイルでよく使う**コネクスタ形式**（Connextra template）で書く。3 行を崩さない。

```
<役割>として、
<やりたいこと>したい。
<なぜなら / それによって避けたいこと>だから。
```

テンプレートでは 3 行がそれぞれ `{{STORY_ROLE}}` / `{{STORY_WANT}}` / `{{STORY_WHY}}` になっている。
埋めるとこうなる:

```html
<blockquote class="story">
  <strong>海外通販を使う買い物客</strong>として、<br>
  <strong>$ 表記の商品を、今日のレートで円換算して見たい</strong>。<br>
  <strong>カードの請求が来るまで日本円でいくらか分からない、を避けたい</strong>から。
</blockquote>
```

「として、」「。」「から。」は**テンプレート側に地の文として入っている**ので、プレースホルダには入れない。

- **役割は「ユーザー」で済ませない。** その人の状況が分かる言い方にする（「海外通販を使う買い物客」「月末に締める経理担当」）
- **3 行目（理由）を省かない。** ここが仕様判断の根拠になる。「切り上げにする」の理由は 3 行目に宿る
- **対象が内部処理で人間の役割が無いとき**（バッチ、内部 API、リトライ機構など）は、無理に人を立てずに削る。削る範囲は **`<p class="label">ユーザーストーリー</p>` と `<blockquote class="story">` の 2 要素**。ラベルだけ残さない。`.scope` と決めごとテーブルは残す

### 4. 書き出す

```bash
# html（既定）
out=/tmp/seq-$(date +%Y%m%d-%H%M)-<slug>.html
# Write ツールで $out に書く（UTF-8）
open "$out"

# md
out=/tmp/seq-$(date +%Y%m%d-%H%M)-<slug>.md
# Write ツールで $out に書く（UTF-8）。open はしない
```

`<slug>` は対象がわかる英小文字ケバブ（例: `login-flow`、`price-jpy`）。
ファイル名のプレフィクスは**スキル名ではなく `seq-`**（タブ補完しやすさ優先）。スキル名と揃えようとして変えない。

**`md` を `open` しない**のは、`.md` に紐づくアプリ（Obsidian など）が開いて、`/tmp` のファイルが意図しない場所で開かれるため。パスを本文に出すだけにする。
**書いたパスを本文に出す。** 上書きしたくない場合があるので、既存ファイルがあれば時刻部分で自然に分かれる。

### 5. 自分で見直す（必須）

**書いた直後に、書いたファイルを Read して読み直す。** 生成した勢いのまま報告しない。
観点は 2 つ。**間違いがないか**と、**読み手にわかるか**。

**「全部確認しました」で済ませない。** 各項目について、**何を見てそう言えるのか**を自分に対して答える。答えられない項目は、確認していない。

**まず機械で判定できるものを潰す**（目視より確実）:

```bash
python3 <このスキルの Base directory>/assets/check.py "$out"
```

`<このスキルの Base directory>` は、このスキル起動時に表示される「Base directory for this skill: ...」の値に置き換える。**固定パスではない** — ユーザー単位のスキルとして入れているかプラグイン経由でインストールしているかでインストール先が変わるため、都度この表示値を使う。

`check.py` は **html / md のどちらも受ける**（拡張子で切り替わる）。
`RESULT=ok` を確認する。NG の中身は形式で違う — html なら未置換のプレースホルダかタグの閉じ忘れ、md ならコードフェンスの閉じ忘れか mermaid ブロック不在。
**`no_steps=1` が出たら実値ブロックを 1 つも拾えていない。** 中身が無いのではなく記法がずれている（html は `class="step"`、md は `## N.`）ことがほとんどなので、記法を直す。
`steps=N (fail=M)` で **`M` が 0 なら失敗系が入っていない** — 原則 3 に反するので足す。
`src_missing=N` が **0 でなければ、出どころを書いていない実値ブロックがある**（html は `p.src`、md は見出し直後のインラインコード）。
合わせて出力される `badges` の並びを、**図の矢印番号と目で突き合わせる**（ここは機械では判定できない）。

**間違いがないか — 事実の照合**

- [ ] **実値はコード・実データに一致するか。** 記憶や推測で埋めた値が混ざっていないか。1 つでも裏が取れないなら、その値を消すか「未確認」と明示する
- [ ] **`.src` のパス・関数名が実在するか。** 書いたファイルを開いて、その関数がそこにあることを確かめる（出どころが嘘だと、読み手はコードを探して迷う）
- [ ] **図の矢印番号と `.badge` の番号が全部対応しているか。** 図にあって実値に無い番号／実値にあって図に無い番号を潰す
- [ ] **1 本のシナリオで通っているか。** 節の途中で商品 ID やユーザーが入れ替わっていないか
- [ ] **計算が合うか。** `pre.code` に書いた途中式を実際に検算する（電卓代わりに `python3 -c` を叩いてよい）
- [ ] **図に数値が紛れ込んでいないか**

**わかるか — 読み手の目で**

- [ ] **この図だけ渡されて実装できるか。** 分岐の条件・丸めの向き・エラー時の挙動が、解釈の余地なく決まっているか
- [ ] **失敗系が入っているか。** `.step.is-fail` が最低 1 つあるか
- [ ] **スコープの外側に手が伸びていないか。** 2 で決めた範囲を超えたステップが増えていないか
- [ ] **専門語がいきなり出ていないか。** 初出の用語に説明があるか
- [ ] **`.step` が 10 個を超えていないか。** 超えたら**ファイルを分けるのではなく、2 で決めたスコープを狭めて描き直す**。1 枚で 1 つの流れが読み切れることを優先する（分割した 2 枚は、たいてい読まれるのが 1 枚目だけになる）

**直したら、直した箇所をもう一度読む。** 修正で番号の対応が崩れることがある。

- **裏が取れなかった値があれば、それを名指しで**。黙って推測値を混ぜない

## mermaid の書き方

```
sequenceDiagram
    participant U as 買い物客
    participant BE as サーバー

    U->>BE: 1. 商品ページを開く
    BE-->>U: 2. 円価格を返す

    alt 期限内のレートがある
        C-->>BE: 6a. hit（7〜9 は飛ばす）
    else 無い
        C-->>BE: 6b. miss
    end
```

- 矢印ラベルは **`N. 説明`** の形。分岐の枝は `6a` / `6b` のように枝番にする
- `->>` は同期呼び出し、`-->>` は戻り。自分への処理は `BE->>BE:`
- `alt` / `else` で分岐、ネストも可。**数値・JSON は書かない**
- `participant` の `as` で日本語表示名を付ける。ID は英字 2 文字程度
- **参加者に対応する実装を追わせたいときは、役割名の後ろに `（）` で実装への手がかりを添えてよい。優先順位はクラス名 → ファイル名 → ディレクトリ名。**
  1. **クラス名** — その参加者の振る舞いが 1 つのクラスに集まっているなら、そのクラス名（`grep -n "^class "` で実在を確認してから書く）。**値の入れ物（`dataclass`・`Enum`・`NewType`・DTO）はクラス名の候補にしない** — 振る舞いが集まっているクラスだけを見る。`grep` が拾ったクラスが戻り値や引数の型でしかないときは、この段を飛ばしてファイル名へ進む
  2. **ファイル名** — クラスが無い（関数ベース）が、振る舞いが 1 つのファイルに集まっているなら、そのファイルのパス（リポジトリルート起点。例: `participant P as 校正（proofreading/__init__.py）`）
  3. **ディレクトリ名** — 振る舞いが同じパッケージ内の複数ファイルにまたがるなら、そのディレクトリのパス（末尾に `/` を付けて区別する。例: `participant T as 翻訳（translation/）`）

  **でっち上げない** — 実在するか `grep` / `find` で確認してから書く。**この優先順位はより具体的なものから当てる**：クラスがあればファイル名やディレクトリ名より必ずクラス名を使う。1 ファイルに収まるのにディレクトリ名で済ませない。役割が複数ディレクトリにまたがるほど広いときは、無理に付けず役割名のままにする
- **ラベルに半角 `#` を書かない。** mermaid が実体参照の開始と解釈し、**`#` 以降が無言で消える**（エラーは出ない）。バッククォートで囲んでも防げない。実測: `1. 「## N.」から拾う` → 描画は `1. 「` だけ。全角 `＃` なら通るが、そもそも**コード片や記号はラベルに書かず実値側に置く**のがこの構成の建て付け

テンプレートは mermaid を jsdelivr の CDN から読む（`mermaid@11`）。ローカルファイルなので CSP 制約はない。
**オフラインだと図は描画されず、mermaid のソースがそのまま等幅で表示される**（`no-mermaid` クラスによるフォールバック）。真っ白にはならないが、絵は出ない。
**配色はライトのみ。ダークモードには対応しない**（`prefers-color-scheme` を見ない）。読み物として 1 枚に閉じるものなので、配色を 2 系統持つ手間に見合わない。

**`.diagram` と mermaid の配色だけは CSS 変数を使わず直値で置いてある。** mermaid は初回描画時に色を SVG へ焼き込み、あとから再描画しないので、変数側を動かしても図は追従できない。`.diagram` の背景（白）と `themeVariables` は同じ値を並べて揃えてある — **片方を変えたら両方直す。**

## md の書き方（引数 `md` のとき）

**貼り込み先の文書には既に文脈がある**ので、スコープ・ユーザーストーリー・決めごと・原則 3 つは**書かない**。図と実値だけを出す。

````markdown
# {タイトル}

{1 行のリード}

```mermaid
sequenceDiagram
...
```

## 2. {見出し}

{説明}

```json
{実値}
```

## 9b. {見出し} ⚠️

{説明}
````

- **実値ブロックは `## N. 見出し`** の h2。`N` は図の矢印番号で、HTML 版の `.badge` と同じ役割を負う
- **見出しの次の行に出どころ**をインラインコードで置く（`` `fx/rate_client.py` · `fetch_rate()` ``）。HTML 版の `.src` に当たる。`check.py` は「見出し後の最初の非空行がインラインコードで始まるか」で見る（**コードフェンス（3 連バッククォート）は出どころと認めない** — 見出しの直後に実値をいきなり置いた形と区別できないため）
- **失敗系は見出しの末尾に `⚠️`** を付ける。md にはクラス属性が無いので、見た目にも出る目印を構造の代わりに使う（`check.py` もこれで数える）
- 見出しは h1（タイトル）と h2（実値）だけに保つ。**貼り込み先の階層に合わせて下げやすくするため**、深い入れ子を作らない
- コードフェンスの言語指定（`json` / `python` / `bash` など）は中身に合わせる。HTML 版の `.c` / `.k` に当たる色分けはフェンスの言語指定に任せる
- **`md` に省略のアコーディオンは無い**（JS も `<details>` も持たせない — 貼り込み先で `<details>` の中の Markdown が効かないことがあるため）。`public` で同一参加者内へ折りたたんだときは、見出しの直後に `> 省略: 一言（full 引数で展開可）` の 1 行を置くだけにする

## マークアップ辞書

`assets/template.html` の CSS が持っているクラス。**新しいクラスを足すより、これで組む**。

| クラス | 用途 |
|---|---|
| `.wrap` | 中央寄せコンテナ（`header` 内 / `main` / `footer` に付ける） |
| `.split` | 1 節（図）と 2 節（実値）を包む。80rem 以上で 2 カラムになり、狭ければ縦積みに戻る。**このブロックだけ左右へ食い出して広がる**（header・0 節・footer は `--wrap` のまま揃う） |
| `.pane-diagram` | `.split` 内の左側。広い画面では sticky で貼り付き、右をスクロールしても図が見えたままになる |
| `.pane-values` | `.split` 内の右側。`.steps` を入れる |
| `.zoombar` | 図の倍率ボタン（`data-zoom` が `-` / `+` / `0`）。`.pane-diagram` 内、`.diagram` の直前に置く |
| `dialog.zoom` | 図をクリックしたときに原寸で開くモーダル。`</main>` の直後に 1 つ置く |
| `.eyebrow` | タイトル上の小見出しラベル |

| `blockquote.story` | ユーザーストーリー |
| `.scope` | スコープ宣言のグレーブロック |
| `.scroll` | テーブルの横スクロール枠（`table` は必ずこれで包む） |
| `td.num` / `th.num` | 数値セル（等幅・桁揃え） |
| `.diagram` | mermaid の枠。中に `<pre class="mermaid">` |

<span class="c">#   ③ 切り上げ   → 4766</span></pre>

## 注意

- **UTF-8 で書く。** 文字化けしたら削除して Write で作り直す
- `pre` の中は**インデントがそのまま出る**。HTML の整形都合で字下げしない
- `&` は `&amp;`、`<` は `&lt;` にエスケープする（クエリ文字列でよく踏む）
- **実在の会社名・実データを載せない。** 題材が実業務なら、footer に断りを入れるか値をぼかす
- **`/tmp` の中身は消える。** macOS は最終アクセスから 3 日で掃除し、再起動でも消える。あとから参照したい内容なら、リポジトリ内の恒久的な置き場所への保存を提案する
